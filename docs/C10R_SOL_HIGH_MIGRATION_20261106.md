# C10R Sol/high integration boundary

This change adds the immutable `SOL_61_HIGH_EXECUTION_V1` profile without
rewriting Astra receipts or changing the default-disabled production path.
The manual host, child controller, accepted-stage reader and final NO-SEND
consumer bind the same exact model, effort, prompt version and source packet.
The legacy economic schema tag is not an execution identity.

The task-local actual transport and bounded public-analysis broker live in
the C10R maintenance workspace. Their exact executed sources, subsequent
offline corrections and guarded Rust source are included in the C10R result
artifact. The original guarded host was rebuilt from pinned official source
and sealed original controls; it was not replaced with an unguarded CLI.

Actual canary outcome:

- Coverage-based representatives: Korean Re and IBM; no ticker-specific policy.
- Korean Re: one real `gpt-6.1-sol` / `high` inference HTTP attempt; HTTP 400
  `model_not_found`, with the official response saying the model is unsupported
  through this ChatGPT-account Codex route. No inference output was accepted.
- IBM: the host rejected before inference because the original two-stage
  control ledger was shared across securities. No IBM inference HTTP attempt.
- No ADJ, Astra fallback, paid API, retry, send or operational activation.

The ledger namespace defect was corrected offline to preserve one two-stage
budget per security, and a task-wide sticky unsupported-model stop was added.
Those corrections were not used to retry the closed attempts. Four focused
offline regressions passed. Local catalog support and thread creation do not
establish server-side model availability; entitlement, route and host-version
causes remain unverified beyond the actual recorded rejection.

The same task independently replayed all 22 common inputs. It preserved 152
qualified financial reference observations across 19 subjects, but this is not
full current Native readiness. Source-only role admission was 51/88 and full
Market Parent admission was 0/2. Current/Strict READY remains 0/22.

Future dispatch requires official support for the exact signed-in model route,
a new explicit finite execution freeze, original live Source/Owner checks and
the unchanged no-retry, isolation and economic-use contracts. This document
does not authorize that next execution or any service/scheduler change.
