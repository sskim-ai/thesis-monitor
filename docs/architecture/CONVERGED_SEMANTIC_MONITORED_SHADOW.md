# Converged Semantic Monitored Shadow

## Status

M12BJ verifies monitored monolithic, Stage 1, Stage 2, and final-composition
compatibility after M12BI established `directional-core-semantic-audit-v1` as
the proof-critical semantic single source.

M12BJ does not add a semantic rule. It freezes the M12BI service ownership,
quarantines the historical Fresh proof from readiness, re-audits the frozen
M12BD fictional proof, and then runs one new monitored shadow generation only
when the normal task-level network gate is ready.

## Execution Boundary

```text
M12BI convergence bundle
  + unchanged 40-case corpus
  + M12BD frozen fictional proof
  + unchanged model-facing surfaces
        |
        v
single task-level network readiness gate
        |
        v
actual active universe (read-only)
  + one frozen packet per ticker
  + canonical view identities
  + frozen canonical-service provenance
        |
        v
monolithic / Stage 1 / Stage 2
        |
        v
canonical semantic re-audit
  + objective hard gates
  + diagnostic decision comparison
```

With `N` active subjects, batch size is four, context count is `ceil(N / 4)`,
and planned calls are exactly three times the context count. There is no
selective rerun, fallback model, judge call, provider refresh, or semantic
hotfix inside a generation.

## Provenance

Each monolithic, Stage-1, and final candidate is re-audited through
`audit_owned_directional_core_semantics`. Applicable hard decisions must name
the canonical service as their source. Lifecycle-inapplicable families are not
counted as bypasses. Legacy compatibility fallbacks cannot participate in a
proof-critical hard decision.

Model-facing prompts, schemas, typed working-capital views, configured-signal
views, financial projection, BusinessDelta, MarketExpectation, and final user
schema are byte-compared with the M12BI base before the network gate.

## Artifact Firewall

Raw prompts, model outputs, transport receipts, working directories, and logs
are stored under a local-only directory outside the repository. The report ZIP
contains only aggregate decisions, enumerated outcomes, hashes, code/docs, and
the artifact index. It contains no raw model artifact.

M12BJ performs no provider fetch, production write, send, registration,
scheduler mutation, monitoring resume, remote push, main merge, or deployment.
Fresh Initial Analysis remains `NOT_READY`, regardless of monitored-shadow
success.

## Policy Handoff

Differences between monolithic and two-stage decisions are diagnostics, not an
automatic correctness vote. An objectively clean shadow hands off to:

```text
DECISION_BOUNDARY_DELTA_HOLDER_POLICY_REVIEW_ON_INTEGRATED_MAIN
```

Main merge, production readiness, and Fresh real-proof readiness remain
`NOT_READY` in M12BJ.
