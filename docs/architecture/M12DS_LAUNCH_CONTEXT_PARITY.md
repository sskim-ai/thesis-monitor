# M12DS Launch Context Parity

Contract: `m12ds-official-codex-launch-context-parity-v1`.

The opt-in M12DS runner restores a host-authorized parent launch. It does not
change the qualified official CLI transport, auth, model, child read-only
sandbox, no-tools controls, or financial semantics. The old M12DR failure
receipts and blind archive remain immutable. Opening state with O_RDWR for
diagnosis performs no writes, SQLite transaction, chmod/chown or credential copy.

`m12ds_launch_context` records safe environment hashes, path/mode/access and
parent ancestry. Historical values absent from M12DM receipts are explicitly
unrecorded. Host-versus-restricted access evidence distinguishes persistent
ownership defects from a parent sandbox restriction.

Only a typed initialization denial within five seconds, with no event bytes
and no final output, upgrades PROCESS_NONZERO to a systemic stop. This small
window classifies startup, not model quality or latency. Ordinary process,
timeout, schema and semantic failures remain batch-local. Certificate trust
errors and binding/tool-surface drift are systemic regardless of that window.

`m12ds_same_blind_reproof` inherits M12DR's Core/A/B/authority/ownership methods.
One tiny canary uses the same invoke method, parent launch and official helper.
Only canary PASS creates a new financial execution generation. Core requests
are byte copies of the already frozen M12DR requests. Source, blind and
financial policy are not refreshed. Full cohort gates remain mandatory.

The original transport helper remains byte-identical to known-good M12DM.
The only M12DR runner edit extracts its existing failure handling into an
override hook. Tests compare all unchanged financial methods to the frozen
implementation. No production caller imports this new runner.

Full accepted Core/A/B is required for sealed AI export. Independent Chat
judgment is not opened, and no reveal or comparison is automatic. Onboarding
`M12DT_NEW_TICKER_ONBOARDING_GATE` is a next-task reservation only.
