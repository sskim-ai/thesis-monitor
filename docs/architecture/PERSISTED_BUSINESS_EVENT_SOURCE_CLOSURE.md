# Persisted Business Event Source Closure

This opt-in, offline path is not registered in production dispatch.

## Ownership

`persisted-source-owned-business-event-v1` accepts an exact, hash-bound source set:
original plan, request intent, response receipt, raw response, logical receipt,
and normalization. It invokes the unchanged news parser, identity/relevance
owners, event classifier and typed stock assembler. It does not accept an old
stock packet, old price, old technical context, or an old PASS receipt.

The original run/acquisition owns the source bytes and publication time. The
current run owns only current eligibility and current security-level inputs.
The state is `PERSISTED_SOURCE_OWNED_BUSINESS_EVENT`, subordinate to the stock
business graph, not an additional acquisition role. The current
`news_and_filing_events` denial remains explicit.

## Permissions

Raw-source resolution does not promote a linked headline to an official filing
or a confirmed economic fact. The canonical authority builder binds the
historical source receipt and resolves its identity with **CONTEXT only**.
Its prior allowed-use set is unchanged. BUSINESS_CONTEXT, OVERALL_DIRECTION,
valuation, entry, confidence and holder-stance authority are not added.
The original `requires_review`, confirmed publication facts and unknowns remain.

## Whole Source

The existing FullSourceRunSeed/composition owner accepts native aggregate
receipts and versioned or persisted-event stock-owner inputs. It independently
replays their owners and canonical source authority. It binds the 24-role
inventory, policy/code fingerprints, both attempts, all 22 stocks, current
acquisition/denial identities, Class-C versions, night publication receipts,
the issuer-only bridge, and persisted-event eligibility.

Supplemental publication records replay in private in-memory databases.
Night receipts replay through the native probe/materializer with explicit
captured bytes. No provider requests, production storage, model dispatch or
renderer invocation occurs. Optional unavailable values stay unavailable.

Offline prequalification is separate from complete live-adapter qualification.
The latter still requires final live requalification after owner changes.
