# Source-Only Seven-Axis Shadow Review

This is an opt-in adapter to the REV59 clean-start controller, not a production
entry point. Qualification results belong to the exact-SHA task report. Importing
these modules does not acquire data, invoke a model, or deliver a message.

## Ownership

`strict_blind_contract` projects source metadata, exact source-authority rows,
typed per-metric coverage and source price/chart facts. It does not read Core,
Pass A/B, B2, or past blind judgments. Current source-authority row hashes use
the existing unified serializer; aggregate authority hashes retain their
existing canonical serializer. There is no alternative-hash fallback.

The seven axes are Overall, fundamental NewBuyer, entry timing, Holder, active
material risk, valuation evaluability, and valuation state. The REVISED REV59
rubric owns their meanings. B2's existing metric-resolution owner is reused;
one denied metric cannot deny another usable metric. Downstream business gates,
model stances, private observation classifications and evaluability verdicts
are not serialized into the blind request. Axis ref permissions are not stances.

Every axis has a judgment, exact source refs, qualitative rationale, and diagnostic
confidence. No numeric literals are permitted in these rationales. This is a
bounded numeric-claim check, not a claim that arbitrary prose is fully understood.
Qualitative prose still requires the post-seal semantic review.

## Execution

`strict_blind_adapter` supplies the real prompt/schema/rubric to the controller.
The plan preserves one blind and one B2 request per subject, two market-scoped
requests, and the existing eight native Core/A/B batches. The existing 600-second,
two transport/form retry policy applies. Schema-valid semantic failures are not
retryable. A fixture callback is not a live model qualification.

`strict_blind_monitoring` calls unchanged native request-capture and semantic
materializers. Legacy acquisition, continuation, dispatch and delivery methods
are not called. Each dependent stage reconstructs its accepted state from sealed
raw upstream outputs and reruns the native validators. Tuple/list subject identity
uses the existing JSON canonicalizer while preserving order. Native payload bytes
remain unchanged; the new controller, not legacy capture-receipt timeout fields,
owns dispatch policy.

The blind builder receives only its allowlisted package, rubric, prompt and schema.
Monitoring builders receive source and causally prior Monitoring outputs, never
blind judgments. Materialized views must be disjoint from the private controller
root. This is declared-input isolation, not an OS sandbox assertion; a live launcher
must independently qualify its process and tool surface before dispatch.

## Comparison

`strict_blind_finalization` is callable only after both output sets are sealed and
the controller enters reveal. It replays native Market/Core/A/B, rebuilds each B2
request, revalidates B2 and blind outputs, then projects the seven axes. The v1
comparator is reused from those exact Pass-B outputs without another model call.

`strict_blind_comparison` classifies equal labels as EXACT_MATCH, unequal native
labels as MATERIAL_DISAGREEMENT, and missing/invalid labels as NOT_COMPARABLE.
No compatible-pair alias is invented. Source binding, contract semantics and
economic disagreement are separate. There is no agreement-rate acceptance
threshold and no historical BUY-to-ATTRACTIVE mapping. The completion callback
recomputes comparison from the seals instead of trusting caller-supplied PASS flags.

No module grants source acquisition, production persistence, Telegram delivery,
main integration, deployment, or architecture acceptance.
