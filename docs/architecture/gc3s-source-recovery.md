# GC3S registration and Source recovery

`registration_seed_restore.restore_operator_registration` restores operator
definitions through the original SQLModel types and `add_watchlist_item`.
The destination must be empty. Identity conflicts block the affected subject.
No old activation, first-eligible session, production eligibility, price data,
AI assessment or Source entitlement is imported. Original onboarding decides
readiness. Pending registration is not active Source membership.

`build_source_release_candidate.build_candidate` uses the original release-time
AST dependency walk. Historical release metadata stays byte-identical. The new
candidate binds the current source and interpreter, remains default OFF and
requires the historical base digest. `--candidate` supports read-only preflight;
it cannot invoke an uninstalled live canary. Lazy application imports remain pinned.

Focused release integration tests require the locally generated, default-off
candidate and frozen historical metadata. They are not a portable full-repository
CI claim. Cold byte tests and registration tests use synthetic isolated data.

The original scoped compiler can plan the 88 chart roles in 36 batches within
20 physical attempts each: KR four-role batches, US daily and US W/M/valuation
batches. This is request planning, not Source Owner issuance. Existing whole
KR/US Market selections compile to 49/48 attempts and cannot run under the
20-attempt batch grant. Their pagination must not be truncated. The current
independent-price selector supports US securities, not KR regular-close intake.

The original Parent still requires current operator account exclusivity. A local
Lane admission covers one enrolled process and does not attest all remote callers.
Neither a restored seed nor a planning hash replaces that requirement. Pending
onboarding, unsupported component partitioning and absent Provider entitlements
remain explicit gates. Financial, Native, valuation and model rights remain OFF.
