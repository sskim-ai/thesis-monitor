# Pending Source preparation (P3F)

This is an offline Source preparation layer, not production activation. The
original prospective Class-C Owner, Global Lane, Worker and Source Parent remain
unchanged. No Source, Market or Native capability is granted by planning JSON.

## Registration and scope

Original onboarding needs identity, SecurityMaster, company profile, investment
logic, initial evidence, baseline assessment and decision readiness. Reconciliation
sets ACTIVE and first eligible session only after the original readiness checks.
Profile population alone does not activate a subject. Evidence collection and
baseline assessment themselves depend on sources, creating a bootstrap dependency.

`pending_source_intake` binds the original process-local operator approval and
five-SELECT capture to a separate short-lived, process/code-bound Source-only
capability. Only the trusted backend adapter may call `record_backend_intake_scope`
with an actual current account-use confirmation. Its boolean is an explicit
trusted control-plane decision, not technical discovery of remote callers. A hash
or model JSON is not a capability. No current confirmation was inferred in P3F.
Consume checks original approval lifetime, capture hashes, generation, membership,
role and newly completed exchange session. Production flags are never imported.

The original Parent accepts only ACTIVE prospective Owners. Its registration
replay and dispatcher contract have not been broadened to this new capability.
`require_live_worker_adapter` explicitly rejects with
`SOURCE_INTAKE_ADAPTER_NOT_PROVEN`; no type substitution or alternate HTTP client
exists. A future versioned original Parent adapter still requires separate review.

## Prices

`ScopedPriceCaptureSelectionV2` adds explicit KR price-only adjusted-daily reads
to the original compiler. V1 remains US-only. The narrow two-row request is not
D1000 coverage. `kr_source_close.project_source_close` calls the original exact
completed-price Owner (including receipt/normalized/raw/calendar verification).
Existing chart receipt bytes can be consumed once without another request; the
binding hash names that same generation, basis and original receipt. It does not
authorize cross-generation sharing or turn adjusted close into regular close.

KR8 completed adjusted-close inputs are structurally routable. Independent
unadjusted `COMPLETED_REGULAR_SESSION_CLOSE` for KR remains unavailable pending
adjustment/corporate-action compatibility evidence. US14 retains usa20590 regular
close and its original technical-compatibility restrictions. Neither path gets
current Native/valuation rights from Source-only intake.

## Market chunks and independent Cold

`market_component_chunks` partitions the original descriptor dependency graph.
It preserves request bytes, complete pagination groups and exchange-discovery
dependencies, repeats required authentication/dependencies explicitly in the
physical budget, rejects retry-enabled plans and caps every chunk at20 attempts.
Repeated discovery responses must agree; they are not silently overwritten.
Unresolved original roles remain unresolved. No Provider entitlement is inferred.
The original KR49 plan contains20-page chains. Authentication makes such a group
21 attempts. The original RequestPlan also requires every previous page in the
same plan, so this version rejects that indivisible group rather than truncating
it or inventing a cross-chunk continuation grant. Synthetic smaller KR plans and
the original US48 plan can be partitioned; this is not KR49 readiness.

Cold reassembly checks exact partition, receipt coverage, generations, sessions,
request/page identities, physical ordinals, hashes, clocks and continuation end.
Metadata describing dispatcher not-selection is not live dispatcher authentication.
It produces `SOURCE_BYTES_REASSEMBLED_NOT_PARENT`, never a Market grant. Real
Provider normalization still owns currency, publication/business-day semantics.
Separate-process synthetic Cold is not evidence of actual financial collection.

The original canonical Market projection also needs a run seed/authority graph,
Class-C publication versions, source windows and macro/overnight inputs. No proven
mapping from this Source-only chunk corpus to that authority graph exists yet:
`SOURCE_CHUNK_PARENT_BINDING_NOT_PROVEN`. This is a scoped integration gap, not a
reason to mark an ETF-only or partial Market result current.

P3F keeps these integration gaps separate from positive synthetic preparation
tests and from current live authorization. It is not full22/Market2 CODE_READY.
