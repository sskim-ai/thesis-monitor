# 16. Standing Storage GC policy — mandatory before NEW full-fresh collection

This section becomes the default policy for future work instructions that start a new full-fresh
generation.

## 16.1 Archive verification prerequisite

A prior expanded generation/report may be deleted only when its immutable result archive has:

- ZIP present;
- `.sha256` present;
- SHA matches;
- ZIP CRC PASS;
- internal manifest PASS with:
  - missing 0;
  - hash mismatch 0;
  - size mismatch 0;
  - extra 0.

Record the immutable archive identity before deletion.

## 16.2 Preserve

Never delete as generation GC:

- current active worktree;
- current branch/ref;
- shared `.git` common object store;
- operating/main state;
- production DB/WAL;
- `.env`;
- credentials/auth/config secrets;
- latest immutable result ZIP + `.sha256`;
- explicitly registered minimal regression fixtures;
- any unique evidence whose archive integrity has not been proven.

## 16.3 Delete eligible expanded data

After archive verification and minimal fixture extraction, delete superseded expanded copies of:

- raw request bodies;
- request intents;
- attempt receipts;
- normalized source rows;
- source-role receipts;
- replay corpora;
- expanded full-source packets;
- unpacked result/report directories;
- temporary provider artifacts;
- duplicate diagnostic exports;

for previous sealed generations.

This may include the REV17 expanded generation/report after:
- its archive is verified;
- Section 12 fixtures are sealed.

Do not delete the REV17 ZIP/SHA archive.

Older sealed R9 expanded generations should also be removed when they satisfy the same archive
conditions and are not the sole owner of a registered regression fixture.

## 16.4 Git worktrees

Storage GC may inspect old completed worktrees, but remove them only when:

- worktree is not active/current;
- `git status --porcelain` is clean;
- no untracked artifact remains;
- commit is preserved by a branch/tag/ref or is otherwise intentionally retained;
- corresponding required result archive is sealed.

Use:

`git worktree remove`

not raw `rm -rf`.

Shared `.git` objects are not part of automatic GC.

Worktree cleanup is secondary; expanded generation data is the primary target.
