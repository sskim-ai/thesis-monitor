# C21Q: original Source version and current Stage

This is an offline, default-OFF boundary. No model, auth, financial request,
database, scheduler or service is enabled. Stacked on PR #35; no merge.

## Exact producer

The task backend extracts the historical app/scripts from one Git commit into
a read-only source directory. A separate OS network-denied Python process runs
the original AnalysisView and build_bundle using original dated Raw/receipts.
Audit hooks also reject sockets, databases, credentials and child execution.
It verifies the entire packet equality, actual imported-source closure, and
Raw/receipt hashes. No old implementation hash is inserted into modern code.

`producer.py` is the finite original-code RPC worker. It admits only rebuild
and close. The original code and financial Owner live in that process; a saved
packet/receipt is not an Owner. Closing it ends this task's capability.

## Separate current consumer

`app/services/versioned_source_replay.py` binds a trusted backend's live
producer RPC, original exact packet, original economic input, current schema,
and current Stage/validator file identity. It rechecks the original producer
and immutable environment. Current-source use and unapproved additional Owner
options are rejected. The same live parent UseRegistry is checked before each
Source read and must be supplied again for output validation; revoked evidence
cannot reach a model merely because the historical producer remains live.
The class is explicitly enabled by a trusted backend,
not reconstructed from a JSON receipt. This does not issue execution approval.

The optional `versioned_source_owner` input in the Unified opinion validator
re-enters that capability and still requires rebuilt == packet. All ordinary
calls use the original current-version build_bundle path unchanged. All
numeric, accounting, evidence-use, schema and economic validation after the
source check is unchanged. Exact class checks reject caller-supplied JSON.

To use this path later, a trusted backend must maintain the isolated producer,
pass its source_loader/economic_loader and live versioned capability into the
existing StageController, keep current schema/request approval and original
model/account/host controls, and obtain a new finite model authorization.
This task does not test or issue an actual accepted model Stage.

## Account proposal, not an activated guard

`account_contract_dry_run.py` is a pure offline proposal evaluator; it cannot
send HTTP or add a Rust route allowlist. Actual routing metadata/account ID,
native auth owner generation and transport headers remain unobserved.
The original logical research account must not be treated as a native account
alias. A future private host capability must bind both distinct namespaces,
source/request/host pins and a one-attempt bootstrap ledger. Default routing
can refresh, proxy-fallback or redirect, so zero retry is not yet established.

Only eight new Source-boundary tests are run, plus task-specific actual Source
replay/negative gates and thirteen pure account proposal cases. Prior C21P/N/O
host tests, builds and probes are inherited, not repeated.
